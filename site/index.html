01 / Security

Quantum-safe, end to end

Elliptic-curve signatures — the ones guarding almost every chain today — fall to Shor's algorithm. Data recorded now can be broken later. Tesserax never used them: post-quantum cryptography is not an option you turn on, it is the only cryptography the chain knows.

ECDSA · Ed25519 · sr25519 Most blockchains
broken by Shor
ML-DSA-87 · FIPS 204 Tesserax, the only scheme
NIST category 5

Signatures

Every account is an ML-DSA-87 key, every transaction an ML-DSA signature. No sr25519, no ed25519, no ECDSA — not even as a fallback.

FIPS 204

Network

Nodes talk over TLS 1.3 with ML-KEM-768 key exchange, and the public RPC refuses any client that cannot do the same.

FIPS 203

Privacy

A shielded pool hides sender, recipient and amount, proven with zero-knowledge STARKs: hash-based, no elliptic curves, no trusted setup.

ZK-STARK

Contracts

Solidity compiled to PolkaVM, a RISC-V machine. No EVM, curve precompiles disabled, and a native precompile to verify ML-DSA signatures.

PolkaVM
02 / AI agents

An economy for machines

Agents need money they can use without a human clicking “confirm” — and owners need hard limits they can trust. Tesserax puts both in the runtime, for any language model.

  • Delegation with limits. A budget per period, a cap per call, allowed recipients and an expiry, enforced by the chain and revoked at once.
  • Registry and reputation. Identity, endpoint and capabilities on chain; ratings only come with a payment, so they cannot be farmed for free.
  • Payment channels. Vouchers signed off chain, one transaction to claim thousands of payments, and HTTP 402 for paid APIs.
  • Task market. Agents order work from each other, the reward held in escrow until the work is approved.
  • MCP server. Any agent speaking the Model Context Protocol holds, spends and earns TESS out of the box.
